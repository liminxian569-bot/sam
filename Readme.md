## 核心架構與分工

### 1. WordBank (外部題庫與動態資料管理)
### 負責人：吳宸緯

* **角色定位：** 負責處理遊戲的核心資料持久化與難度抽題邏輯。 [cite: 吳宸緯]
* **技術要點：**
    * **外部題庫整合：** 實作 `ifstream` 檔案串流機制，將原本寫死在程式碼的題庫移至外部 `words.txt`，達成資料與邏輯分離。 [cite: 吳宸緯]
    * **自動化資料分流：** 在讀取主題庫時，利用 `eng.length()` 判斷單字長度，自動將單字分類並生成 `easy.txt`、`normal.txt` 與 `hard.txt`。 [cite: 吳宸緯]
    * **動態難度載入：** 根據玩家選擇的難度參數，動態選取對應的難度檔案進行讀取，實現資料解耦。 [cite: 吳宸緯]
    * **隨機抽題與挖空：** 結合隨機種子（Seed）確保每局獨特性，並開發自動挖空演算法，針對不同長度的單字執行遮蔽。 [cite: 吳宸緯]

### 2. GameManager (遊戲邏輯與多媒體回饋)
### 負責人：李旻憲

* **角色定位：** 擔任遊戲「裁判」，負責所有視覺輸出、血量監控與成就記錄。 [cite: 李旻憲]
* **技術要點：**
    * **Pet 系統 (圖形化血量)：** 整合 `Pet.h` 負責圖形化血量顯示，根據玩家當前血量與猜測對錯動態切換寵物狀態。 [cite: 李旻憲]
    * **Scoreboard 系統 (連勝紀錄)：** 整合 `Scoreboard.h` 負責記錄玩家的連勝次數（Win Streak），提升遊戲挑戰性。 [cite: 李旻憲]
    * **比對機制：** 即時比對玩家輸入與正確答案，更新題目顯示狀態。 [cite: 李旻憲]
    * **視覺輸出：** 負責繪製 ASCII 介面、顯示目前題目狀態與剩餘血量。 [cite: 李旻憲]
    * **勝負判定：** 監控遊戲是否達到勝利（單字補全）或失敗（血量歸零）條件。 [cite: 李旻憲]

## 遊戲規則說明

### 1. 遊戲開始
系統會提示玩家選擇難度，並從對應題庫隨機抽取單字，以隱藏模式顯示（例如：`c_mp_ter`）。

### 2. 玩家操作
玩家輸入完整單字或字母。為了保持畫面整潔，系統在每次輸入後會清空螢幕 (`system("cls")`) 以顯示最新狀態。

### 3. 判定邏輯
* **猜對了：** 對應位置的底線轉為正確字母，寵物顯示正面情緒，維持血量。
* **猜錯了：** 扣除 1 點血量，寵物顯示負面情緒。
* **無效輸入：** 若輸入重複或無效字元，系統會給予警告且不扣血。

### 4. 勝負判定
* **恭喜獲勝：** 在血量歸零前補全單字，連勝紀錄（Scoreboard）加一。
* **遊戲失敗：** 猜錯 3 次（血量歸零）即結束，連勝紀錄歸零並公佈答案。
